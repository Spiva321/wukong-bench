# WukongBench

Автоматический запуск **Black Myth: Wukong Benchmark Tool** из Steam: два прохода
с разными настройками — CPU-тест и GPU-тест — с автоматическим разбором результатов.

Консольная утилита на **C# / .NET 8**. Windows.

---

## Что делает

Один запуск — полный цикл без участия человека:

1. находит установку Benchmark Tool через Steam;
2. сохраняет резервную копию конфига настроек;
3. применяет профиль **CPU-теста**, запускает бенчмарк, проходит его меню, ждёт результат;
4. применяет профиль **GPU-теста**, повторяет;
5. сверяет заданные настройки с теми, что реально применила игра;
6. печатает отчёт и возвращает конфиг пользователя как было.

## Требования

- Windows 10/11 x64
- [.NET 8 SDK](https://dotnet.microsoft.com/download/dotnet/8.0) — только если запускаешь через `dotnet run`.
  Готовый `.exe` из `publish/` работает без установленного .NET.
- **Steam запущен** — у бенчмарка проверка прав через Steam API, без неё он не стартует
- Бенчмарк установлен из Steam (бесплатное приложение, **AppID 3132990**) и **хотя бы раз
  запускался вручную** — игра создаёт конфиг только при первом запуске
- Права на запись в папку установки бенчмарка (обычно хватает обычных прав, если Steam
  стоит не в `Program Files`; иначе запусти от администратора)

Во время прогона **не трогай мышь и клавиатуру** — инструмент сам нажимает кнопки меню.

## Запуск

```bash
dotnet run --project src/WukongBench
```

Путь к установке ищется автоматически: реестр Windows → `steamapps\libraryfolders.vdf` →
стандартные папки Steam. Если не нашлось — можно указать вручную первым аргументом:

```bash
dotnet run --project src/WukongBench -- "D:\SteamLibrary\steamapps\common\Black Myth Wukong Benchmark Tool"
```

### Готовый .exe

```bash
dotnet publish src/WukongBench -c Release -r win-x64 --self-contained true -p:PublishSingleFile=true -o ./publish
```

Получится `publish/WukongBench.exe` — один файл, .NET на машине не нужен.

### Как найти папку установки вручную

Steam → ПКМ по **Black Myth: Wukong Benchmark Tool** → Управление → Просмотреть локальные файлы.

## Настройки двух проходов и почему такие

Общая часть для обоих тестов: полноэкранное окно, **Vsync выкл**, **ограничение FPS выкл**,
**генерация кадров выкл**, **размытие в движении выкл**.

> Генерация кадров выключена не просто так. Она подставляет искусственные кадры: FPS
> завышается, а соотношение времени кадра CPU и GPU переворачивается наизнанку. Проверено
> на реальном прогоне — при генерации кадров инструмент показывал 96.9% «CPU-лимита» при
> видеокарте, загруженной на 77%. Это мусор, а не измерение.

### CPU-тест — снять с видеокарты максимум работы

| Настройка | Значение | Зачем |
|---|---|---|
| Масштаб рендеринга | **50%** | при окне 1920×1080 игра рисует 960×540 — вчетверо меньше пикселей |
| Все 10 параметров качества | **минимум** | тени, глобальное освещение, отражения, постобработка, растительность — всё дешевле |
| Трассировка лучей | **выкл** | самый дорогой для видеокарты эффект |

**Идея:** когда видеокарта от��исывает кадр быстрее, чем процессор его считает, узким
местом становится процессор. FPS начинает отражать именно его производительность.

**Почему не 25%:** Unreal обычно всё равно ограничивает масштаб снизу. Просишь меньше —
получишь не то, что просил. 50% — надёжный минимум.

### GPU-тест — сделать видеокарту узким местом

| Настройка | Значение | Зачем |
|---|---|---|
| Масштаб рендеринга | **100%** | ни одного пикселя не экономим |
| Все 10 параметров качества | **максимум** | самые дорогие шейдеры на каждый пиксель |
| Трассировка лучей | **вкл** | самый дорогой эффект в игре |

**Идея:** при полном разрешении и максимуме эффектов GPU почти гарантированно становится
узким местом, и FPS отражает именно его.

**Оговорка:** трассировка лучей зависит от поколения видеокарты сильнее прочих настроек.
Для честного сравнения карт разных поколений нужен отдельный прогон без неё — это
переключается в `BenchmarkProfile.Gpu`.

### Чего инструмент НЕ трогает — и почему

| Ключ | Почему не трогаем |
|---|---|
| `ScreenResolution` | хранится **индексом** в выпадающем списке. Подтверждено только, что `0` = 1920×1080. Какой номер у 1280×720 — неизвестно |
| `SuperResolutionSampling` | не знаем, какое значение у режима «без апскейлинга». Запишем наугад — бенчмарк упадёт на старте |
| `QualityLevel` | в конфиге 6, в отчёте бенчмарка 3 — шкала неизвестна. Похоже на индекс пресета: применится пресет целиком и затрёт наши ключи |
| `RtxLevel` | при `Rtx=1` игра возьмёт то, что уже записано, `1`. Допустимый диапазон неизвестен |

Всё это перечисляется в отчёте как «не задавалось инструментом» — честно, без выдумок.

## Почему результату можно верить

Бенчмарк возвращает в JSON **эхо применённых настроек**. Инструмент сверяет каждое значение:
что мы задали в конфиге против того, что игра реально использовала. Если расходится — в
отчёте будет строка `РАЗМ` и предупреждение.

Это защищает от тихой порчи замера. Без такой проверки возможен сценарий: инструмент пишет
`sg.ResolutionQuality=50`, игра при старте решает, что главное у неё `ImageQuality`,
пересчитывает и возвращает `66.7`. Тест проходит, показывает правдоподобные числа, отчёт
говорит «масштаб 50%» — а на самом деле тест шёл на 66.7%. Обнаружить это невозможно.

Дополнительно считается **доля кадров, где CPU считал кадр дольше GPU** и наоборот. Это
прямое доказательство, что нагрузка легла туда, куда мы хотели: в CPU-тесте эта доля должна
быть высокой, в GPU-тесте — низкой. Если не сходится, отчёт предупредит.

## Формат вывода

Отчёт печатается в консоль и сохраняется на рабочий стол в
`WukongBench\results\<дата-время>\`:

```
report.txt              — итоговый отчёт
cpu_raw.json            — сырой результат CPU-теста
gpu_raw.json            — сырой результат GPU-теста
```

В отчёте: характеристики ПК, сравнительная таблица двух проходов, подробности по каждому,
применённые настройки с обоснованием, результат самопроверки, предупреждения.

### Две находки в самом бенчмарке, о которых стоит знать

**`FPS95` — это не 95-й процентиль, а 5-й.** Проверено на реальном файле: 5-й процентиль
посчитанного массива даёт 68.15, в поле стоит 68. По смыслу это «1% low» — больше значит
лучше. В отчёте подписано соответственно.

**`CPUUsage` и `CPUAvg` — заглушки.** В реальном файле во всех 8259 записях `CPUUsage` равен
ровно 1.0, `min == max == 1.0`. Это не замер. Загрузка процессора считается по
`CPUFrameTime` — единственному живому признаку.

## Технические решения, о которых стоит знать

**Настройки лежат в двух местах.** В `UISettingData` — то, что видит меню игры (значения
`1..5`). В `[ScalabilityGroups]` — группы качества Unreal (`0..4`). Связь: **значение меню
минус 1**. Меняем оба, иначе поведение непредсказуемо.

**`FileShare` при чтении JSON.** Бенчмарк держит файл открытым, пока пишет. Без
`FileShare.ReadWrite | FileShare.Delete` чтение невозможно.

**BOM при записи конфига.** Игра пишет `GameUserSettings.ini` без маркера кодировки. .NET
при записи UTF-8 по умолчанию BOM **добавит**, и игра не найдёт первую строку секции —
настройки сбросятся на дефолтные, а тест пройдёт молча не на том. Отслеживается флаг
`_hasBom` и кодировка создаётся явно.

**Процесс убивается, а не закрывается.** При штатном выходе игра сохраняет свои настройки
и перезаписывает конфиг — тогда второй проход пошёл бы на настройках первого.

**Результат проверяется до клика.** На экране итогов есть кнопка «Пройти заново» — клик по
ней запустил бы лишний прогон.

**Кликаем только когда наше окно на переднем плане.** Иначе клик ушёл бы в чужую
программу.

**Снимок папки результатов до запуска.** Иначе инструмент возьмёт вчерашний результат и
выдаст за свежий.

**Конфиг восстанавливается в `finally`.** Даже при падении. Плюс `RecoverAfterCrash()`
на старте — если прошлый запуск убили, бэкап вернётся.

**`InvariantCulture` в `Program.Main`.** В русской локали `16.865` вывелось бы как `16,865`
— легко прочитать как шестнадцать тысяч.

## Ограничения

- Прохождение меню сделано через Win32 `SendInput` → работает **только на Windows нативно**.
  В `README` не описано, как включить WINE/Linux, потому что это не тестировалось.
- Прохождение меню «слепое» — по эталонным координатам в `BenchmarkRunner.cs`. Если бенчмарк
  обновится и кнопки переедут, координаты нужно поправить.
- Четыре параметра качества (глобальное освещение, отражения, эффекты, детализация шейдеров)
  бенчмарк в JSON не возвращает — проверить их применение невозможно. В отчёте это указано.
- `Win32_VideoController.AdapterRAM` — 32-битное поле, у видеокарты с 8 ГБ покажет 4 ГБ.
  Поэтому в отчёте есть и это значение с пометкой о занижении, и точное из отчёта бенчмарка.

## Возможные проблемы при запуске

| Симптом | Причина |
|---|---|
| `Failed entitlement check with Steam API` | не запущен Steam |
| `Не удалось найти установку` | бенчмарк не установлен или ни разу не запускался вручную |
| Бенчмарк не проходит меню | координаты кнопок устарели — править `BenchmarkRunner.cs` |
| Меню прошло, но JSON не появился | см. `WaitBeforeClose` в `BenchmarkRunner.cs` |
| Настройки в отчёте помечены `РАЗМ` | игра пересчитала то, что мы задали. Смотрите значения в таблице |
